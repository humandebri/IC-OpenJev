# 現行openJevと追加学習済みModernBERT-Ja-130Mの比較

実施日：2026-11-18（日本時間）。前回の70M / 130M比較と同じ新しいテスト48件を使い、現在稼働しているopenJevも実測しました。

この条件では、追加学習済み130M版の方が高精度でした。比較対象は「現行システム」と「用途別に学習した候補」であり、日本語事前学習・追加学習・量子化などの効果を個別に切り分けた実験ではありません。

## 同じ48件すべてを処理した場合の精度

| 指標 | 現行openJevの重み・ローカル推論 | 追加学習済み130M・3seed平均 |
| --- | ---: | ---: |
| 部署 | 43.8%（21/48件） | 94.4% |
| 優先度 | 35.4%（17/48件） | 91.0% |
| 部署・優先度が両方正解 | 16.7%（8/48件） | 86.1% |
| 高優先度16件の見落とし | 1件 | 各seedとも0件 |

openJevは現在の公開queryと同じ重み・tokenizer・質問文・候補・temperature=1・棄権なしの条件です。ただし公開queryの52トークン制限があるため、全48件の分類精度は、同じRust推論実装を使うローカル用probeで最大128トークンまで処理して測りました。実入力は49〜68トークンで、切り詰め・英訳・候補変更はしていません。

公開APIで回答できた13判定は、ローカル版と選択が13/13一致しました。ローカルpackのdigestも、公開APIが返したモデル識別子と一致しています。これはAPI上限内での照合であり、上限外の入力をcanister上で実行した証明ではありません。

優先度では48件中41件を「高」、7件を「通常」とし、「低」は選びませんでした。高優先度の見落としが少なくても、多数の低・通常の問い合わせを高優先度へ振り分けています。

130Mは前回、学習132件・検証24件で選択した3つのcheckpointの保存済み結果を再利用しています。今回のopenJev結果に合わせた再学習、checkpoint変更、良いseedだけの選択は行っていません。テスト48件は同じケースの繰り返しなので、3seed分を144件の独立したテストと扱いません。

## 現在の公開APIで実際に処理できる範囲

| 項目 | 部署 | 優先度 |
| --- | ---: | ---: |
| 送信件数 | 48 | 48 |
| 正常に回答できた件数 | 6 | 7 |
| 入力予算によるCapacityエラー | 42 | 41 |
| 回答できた中での正解数 | 3/6 | 1/7 |

全部署・優先度の96 query中83 queryがCapacityで拒否されました。2項目とも回答できたチケットは6/48件で、その両方が正解だったものは1件です。未回答を黙って除外した正解率を全体の精度としては報告しません。これらの拒否はローカル推論での21/48・17/48という精度とは分けています。

同じ文章でも、openJevでは本文に加えて質問文と候補も入力に含まれ、130Mの固定分類ヘッドでは本文だけを入力します。トークン数の差を日本語tokenizerだけの効果としては扱えません。

## 実装・計測条件

- 匿名の公開 `decide_query` を96回使用し、開始・終了時にモデルとquery上限が変わらないことを確認しました。canister更新・設定変更・有料updateは行っていません。
- ローカル用probeは `crates/verdict-candle/src/bin/ticketing_probe.rs`。既存のpack loader、checked prompt、tokenizer、INT8推論を再利用し、queryの5B命令予算は適用しません。
- 比較CLIは `web/ticketing/scripts/compare-current.ts`。参照レポートの完了状態と入力ハッシュを検査し、API・nativeの全応答とエラー、使用したコード・バイナリ・pack・参照記録のハッシュを保存します。
- APIはネットワーク込み、nativeはCPU、130Mの前回測定はMPS GPUです。これらの応答時間をモデルの速度差として直接比較しません。
- 失敗を含む全件ベースの精度と、回答があったものだけの精度を分離する集計テストを追加しました。

## 結論と限界

日本語チケット用の候補としては追加学習済み130M版が有望です。現行openJevは入力上限を外してもこの48件では低精度であり、公開APIの入力制限だけを緩めても分類品質の問題は残ります。

ただし、これは架空の短い問い合わせによる小規模な比較です。130Mの実務精度、判断保留や複数要件への対応、ICPでの実行可否・費用は未検証です。既存UIのモデルと公開保留判断は変更していません。
